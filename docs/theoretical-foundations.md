# DecisionJudge 理论资料与内容扩充建议

> 项目探索与资料核对日期：2026-09-21。本文是研究与产品设计建议，不代表新增功能已经实现。

DecisionJudge 最适合围绕“明确价值 → 比较方案 → 验证未知 → 控制投入 → 行动与复盘”扩充内容。第一优先级是完善现有评分、权重和解释的理论基础；随后用信息价值、动态退出和决策复盘支撑产品方向中的“验证行动”与“选择账单”。

本文结合项目文档与代码静态阅读，提供 10 个理论方向、4 张可改写为界面文案的提示卡，以及 16 项资料。外部资料采用定向检索；书目核验、摘要阅读与全文节选阅读分别标注，未进行系统综述或全部文献全文审读。

## 1. 项目现状与理论落点

项目是 React + TypeScript + Vite 的本地单用户决策工具，使用 IndexedDB 保存记录。主要场景为升学或就业、换工作、迁居和重大消费。基础流程是目标与约束、方案、权重、评分、结果，再保存决策快照。

| 项目依据 | 当前可确认的内容 | 理论扩充的意义 |
| --- | --- | --- |
| `README.md`；`src/domain/evaluation.ts` | 核心计算是各维度 1–10 分的加权和；解释机会成本、沉没成本及简单权重扰动 | 建立多属性价值测量、摆幅赋权、敏感性范围及解释规则 |
| `src/domain/templates.ts` | 模板已有推荐维度、默认权重和高低锚点 | 让模板说明评分对象、量尺、时间范围、证据与重复计分风险 |
| `src/domain/types.ts`；`src/App.tsx` | 高级模块主要是布尔开关，尚无完整情景、风险函数、现金流等输入与计算 | 风险、折现等理论应标为后续方法依据 |
| `docs/product-direction.md` 第 5.5、6 节 | 规划待验证问题、来源、日期、信心与验证行动 | 用信息价值解释“下一步最值得查什么” |
| `docs/product-direction.md` 第 4.3、5 节 | 规划计划与实际投入、可回收投入、承受边界和选择账单 | 用未来增量、实物期权与阶段复评组织内容 |
| `docs/requirements.md` 第 13 节 | 已有快照；实际结果与系统复盘属于后续版本 | 用实施意图、预测评分和结果偏差补全行动后的学习流程 |

## 2. 优先扩充的理论与资料

### 2.1 多属性价值理论与摆幅赋权：先让评分有明确含义

**对应内容：** 设置权重、评分锚点、结果解释。主要资料为 [R1]、[R2]、[R3]。

现有加权和更接近确定性多属性价值模型（MAVT）的简化形式。若要称为包含风险偏好的多属性效用模型（MAUT），还需要对不确定后果、概率和效用作进一步建模；字段名 `utility` 本身不意味着这些条件已满足。

推荐补充四个解释：

1. 分数表示对后果的偏好强度，不是该后果发生的概率，也不是证据的可信度。
2. 权重应结合评价范围。例如，“年收入从 18 万提高到 25 万”与“单程通勤从 90 分钟缩短到 30 分钟”，哪段改善更值得？这比只问“收入和通勤哪个重要”更具体。
3. 高低锚点要描述同一类后果。不能一端写收入高低，另一端写是否掌握充分信息。
4. 加权模型允许补偿；不可补偿的底线应先作为约束。维度还应检查偏好独立性、重复计分和量尺一致性。偏好独立性不等同于统计上不相关。

开发侧可采用：

\[
V(a)=\sum_j w_jv_j(x_{aj}),\qquad w_j\geq0,\quad\sum_jw_j=1.
\]

其中，原始表现是 `x`，价值映射是 `v`，权重是 `w`。保留现有 1–10 分界面也可以；改成 0–100 并不会自动提高量尺有效性。若采用固定 1–10 锚点且假定等距，线性变换 `(score−1)/9` 仅改变单位，不会凭空提高可靠性。

**可新增内容：** “如何设定高低锚点”“如何做摆幅赋权”“重复计算检查”三张方法卡；在结果页区分“主要得分来源”和“A 相对 B 的差异贡献”。后者可用 `w_j × [v_j(A)−v_j(B)]`，各维度相加等于两个方案的综合分差。

**适用边界：** 默认权重是可修改的起点，不能作为已验证的普适偏好。增加 AHP、TOPSIS 等算法不能替代对输入量尺和模型适用条件的检查。

### 2.2 价值导向思考：在给方案排序前，先补全方案

**对应内容：** 明确目标、列出方案、模板设计。主要资料为 [R4]、[R1] 第 6.2.4、6.2.16 节。

用户经常把手段写成目标，如“必须考研”；进一步追问可能发现真正追求的是进入某类工作、获得研究训练或改善长期收入。先明确目的，才有机会形成不同路径。

**可新增内容：** 目标树、目的与手段辨认、方案生成问题。对“留任还是辞职”提示考虑内部转岗、先核实条件、分阶段转型等方案；这些只是待检验候选项，不预设对用户可行。对每个方案保留硬约束与现实可行性判断。

**示例问题：** “如果不能使用你目前想到的办法，还能通过什么路径达到同一目标？”

**适用边界：** 扩充方案要有停止条件。更多方案不自动带来更好决策，也不应为了凑数量增加明显不可行的选项。

### 2.3 信息价值与停止搜索：什么信息值得继续查

**对应内容：** 评分依据、待验证假设、验证行动。主要资料为 [R5]；[R1] 第 6.2.17 节也讨论“继续分析能否影响决定”。

信息有价值，是因为它可能改变行动，并改善采取行动后的预期价值。某项信息即使非常不确定，若所有可能答案都不改变选择、行动方式或可行性判断，继续搜集它的决策价值仍可能很低。

项目方向中的“影响 × 不确定程度 ÷ 验证成本”适合作为启发式提示，不能标成已计算的期望信息价值。正式的期望样本信息价值可写为：

\[
EVSI=\mathbb E_Y\left[\max_a\mathbb E[U(a,\theta)\mid Y]\right]
-\max_a\mathbb E[U(a,\theta)].
\]

`θ` 是未知状态，`Y` 是拟获取的证据。是否获取信息还要考虑获取成本与延迟成本，并在一致的价值尺度上比较；不能把 1.5 个主观分直接减去 200 元。

**可新增内容：** 一张验证卡记录“假设—可能答案—答案是否改变选择—验证方式—成本与耗时—来源—更新日期”。先提供定性版本，再考虑有明确概率与效用输入的计算版本。

**示例问题：** “如果新岗位实际每周加班超过 10 小时，你会改选留任吗？能通过什么渠道核实？”

**适用边界：** 高敏感维度不一定是最值得查的维度，还要看能否查清、信息可信度以及改变行动的收益。硬约束的未知状态可能直接影响方案是否可行，应优先辨认。不要在基础模式要求用户编造概率。

### 2.4 敏感性与稳健性：结果在什么条件下会改变

**对应内容：** 结论稳定性、相对优势、情景比较。主要资料为 [R1] 第 6.2.14 节、[R2]。

建议将“稳定”改写为有范围的陈述，例如：“在本次检查的权重范围内，第一名未改变。”这与现实成功概率是不同概念。

**可新增内容：** 权重变化阈值、评分区间、关键假设翻转点、跨情景排序。若概率没有依据，可以先并列展示不同情景，保留“无法给出可信概率”的状态。

开发侧单维扰动可固定选定权重 `w_k'`，其他权重按原比例分摊剩余额度：

\[
w_j'=w_j\frac{1-w_k'}{1-w_k}\quad(j\ne k),\quad 0\leq w_k'\leq1.
\]

这要求 `w_k≠1`，边界情况另行处理，且必须始终按维度 ID 对齐评分和权重。该路径也只是一种敏感性检查；同时改变多个输入需要另行定义分析范围。

**适用边界：** 抽样权重下的“第一名占比”依赖人为设定的抽样分布，不能直接叫“选对概率”。敏感性分析不能修复遗漏的重要维度或错误的评分依据。

### 2.5 沉没成本与承诺升级：用未来增量评价继续或退出

**对应内容：** 已发生投入、最大允许损耗、选择账单。主要资料为 [R6]。

区分四类量：已发生且无法回收的成本、仍可回收的价值、从现在起的新增投入、退出或转换产生的未来成本。做继续/退出比较时，应比较后面三类及未来收益，不能因为历史投入变大就提高“继续”的评分。

**可新增内容：** “从今天开始”复评表，包括继续、调整、暂停、退出各自的未来收益、新增支出、回收价值、违约或转换成本，以及当前资源约束。

**示例问题：** “如果今天第一次面对这个选择，且处在相同的现金、时间与技能状态下，你还愿意投入下一阶段吗？”

**适用边界：** 忽略沉没支出本身，不等于忽略过去形成的技能、信息、合同义务或当前现金余量。达到投入阈值应触发重新评估，不机械要求退出。机会成本与净优势也要分开：前者是最佳被放弃替代项的价值，后者是两个方案的价值差，不能再重复扣分。

### 2.6 实物期权与可逆性：把一次性决定拆成可学习的阶段

**对应内容：** 试用、试住、小项目验证、阶段投入和退出条件。主要资料为 [R7]。

当投入具有不可逆性、未来不确定，而且等待或小规模尝试能获得信息时，保留后续选择权可能有价值。因此，某些决定可以分为“先验证一部分—看到结果—再决定是否扩大投入”。

**可新增内容：** “最小试行方案”“下一阶段投入上限”“复评日期”“哪些信号触发继续或调整”“退出可回收什么”。例如，迁居前先短住以验证通勤与生活条件，但短住也有成本且可能不能代表长期体验。

**适用边界：** 等待会付出机会流失和延迟成本，可逆性不是免费收益。金融期权公式不能直接套到个人生活选择上；初期应借鉴结构化思考，不输出缺少参数依据的“期权价格”。

### 2.7 实施意图：把最终选择连接到一个可执行动作

**对应内容：** 最晚开始时间、下一步行动、障碍应对。主要资料为 [R8]、[R9]。

实施意图区分“我想达到什么”与“在什么情境下执行什么动作”。它可以为保存快照后的第一步提供结构：如果某个明确情境发生，那么就在指定地点执行具体动作。

**可新增内容：** `触发情境 / 下一步动作 / 时间地点 / 可能障碍 / 替代安排`。将“准备换工作”改成“周四晚饭后，在书桌前用半小时核对书面录用条件；如加班，则周六上午完成”。

**适用边界：** 文献可支持将此作为行动设计候选机制，不能证明该应用已提高执行率。计划应聚焦用户可控制的行为，不能保证录用、升学或其他外部结果。

### 2.8 决策日志、结果偏差与预测评分：复盘时分开过程和结果

**对应内容：** 不可变快照、事前预期、实际结果、复盘。主要资料为 [R10]、[R11]、[R12]。

好过程可能遇到坏结果，坏过程也可能侥幸成功。复盘应分别检查当时掌握的信息、目标与约束、方案比较、执行情况和外部变化，而不是仅凭最终结果评价当初的判断。

**可新增内容：** 快照记录可检验的事前预期、预测截止日、成功标准和关键假设；到期回填实际结果，保留当时记录，避免事后改写。

如果用户积累足够多、定义清楚的二元预测，可使用常见二元形式的 Brier 分数：

\[
BS=\frac1N\sum_{i=1}^N(p_i-y_i)^2,\quad y_i\in\{0,1\}.
\]

例如，事前预测“入职三个月内可独立完成约定任务”的概率为 0.7，事后发生则记为 `(0.7−1)²=0.09`。例子仅说明算法；事件、任务标准和核验方式必须事先定义。Brier 原文使用类别概率评分，以上为常见二元简化约定。

**适用边界：** Brier 分数评价预测表现，涉及校准与区分能力等因素，不是整个决策的质量分。单次或少量异质人生事件不足以评价一个人的长期概率校准，更不能据此自动贴认知偏差标签。[R12] 是结果偏差的预注册重复研究，使用实验情境，不能直接推断本应用的干预效果。

### 2.9 风险偏好、前景理论与跨期选择：拆开三类不同问题

**对应内容：** 后续情景、风险、折现模块。主要资料为 [R2]、[R15]、[R16]。

需要区分：后果本身有多好、后果发生的概率或分布、用户对风险和时间的取舍。前景理论用于理解参照点、收益损失表述和概率权重等行为现象；它是描述性理论，不能当作所有用户都应遵循的规范规则。风险厌恶与损失厌恶也不是同义词。

跨期现金流可在明确币种、时间点、名义或实际口径后计算净现值：

\[
NPV=\sum_{t=0}^{T}\frac{CF_t}{(1+r)^t}.
\]

**可新增内容：** 情景概率与评分信心分开录入；现金流原始表、折现假设与不同折现率的结果并列；“相同选择用收益表述和损失表述，偏好是否变化”的自查卡。

**适用边界：** 不自动赋予统一风险厌恶或损失厌恶参数，不把所有时间与健康后果强制货币化。跨期偏好研究与现金流折现是相关但不同的问题。[R16] 用于跨期偏好背景阅读，不能直接提供适用于用户的折现率。若风险已计入基础评分，新增风险调整需检查重复计算。

### 2.10 有限理性与满意化：为轻选择设定合适的投入预算

**对应内容：** 轻选择、深度选择切换、渐进式披露。主要资料为 [R13]、[R14]。

人做选择需要消耗时间和认知资源。对低代价、易撤销的小事，可以先设满足条件的门槛，在可接受集合中快速选择；对重要、不可逆或不确定性高的选择，再进入更完整的比较流程。

**可新增内容：** 决策前询问重要程度、可逆性、时间预算与关键未知；轻模式只显示少量约束和可接受选项；当用户发现重要代价或新底线时允许升级深度模式。

**适用边界：** “选项多必然导致选择困难”不是普遍规律。选择过载的元分析 [R14] 提醒其效应受情境影响。分步流程、限制换选次数或双模式是否改善体验，需要实际用户验证，不能从理论直接推出。

## 4. 理论内容落地前需要对齐的实际能力

以下是静态阅读确认的能力边界，不是本次已修复的内容：

1. **高级模块说明。** `src/domain/types.ts:47` 的设置仅为开关；`src/domain/evaluation.ts:20` 记录开关，实际仍执行基础加权；`:61` 却提示专业模块已包含在结果中。理论扩充应先区分“预留入口”与“参与计算”。
2. **敏感性计算。** `src/domain/evaluation.ts:67` 过滤零权重维度，但 `:81` 按完整维度数组下标读取权重，会出现错配；`:73` 的等额扣减可产生负权重。例如 `[0.98,0.01,0.01]` 可变成 `[1.03,−0.015,−0.015]`。这些问题可能使现有稳定性判断失真，应先修正维度对齐和非负权重约束，再提供可信的检查范围说明；仅调整文案不足以解决。
3. **约束状态。** `src/domain/evaluation.ts:10` 只排除明确不可行方案；未知和未填状态仍被保留。`src/App.tsx:186` 创建约束时使用空的评估表。应让“已核实可行”和“尚未排除”有不同含义。
4. **证据记录。** 类型中有 `evidence`，但当前向导评分界面 `src/App.tsx:202` 主要只有分数输入；尚无来源、日期、事实或假设标记。信息价值与校准功能需要这些基础记录。
5. **优势解释。** `src/domain/evaluation.ts:37`、`:45` 将自身贡献排序用于 `strengths/weaknesses`，不等于相对其他方案的优劣。当前结果页并未直接展示这两个数组；其 `decisiveCriteria` 使用全方案极差，也不等于第一名超过第二名的具体原因。

## 5. 内容扩充顺序与验证方式

| 阶段 | 建议交付 | 为什么先做 | 一项真实用户验证指标 |
| --- | --- | --- | --- |
| 第一阶段：比较基础 | 评分与锚点说明、摆幅赋权、模型条件、相对差异解释；对齐高级能力说明，修正敏感性计算并说明检查范围 | 直接改善现有核心流程的可解释性 | 完成任务后，能正确说明最高权重对应哪段具体改善的用户比例 |
| 第二阶段：证据与投入 | 待验证假设、来源与日期、验证行动、未来增量、投入与复评边界 | 支撑已规划的信息价值和选择账单 | 七天内完成至少一项事前登记验证行动并回填结果的用户比例 |
| 第三阶段：行动与复盘 | 如果—那么计划、事前预期、结果回填、继续或调整理由 | 让一次决定留下可学习记录 | 到约定复盘日后七天内完成“预期—实际—下一步”的用户比例 |

这些指标用于早期可用性与行为验证，不自动证明决策结果更优。应同时记录未完成原因，避免把流程困难解释为用户缺乏动力。风险函数、完整概率模型和个性化校准可在基础记录形成后再逐步加入。
