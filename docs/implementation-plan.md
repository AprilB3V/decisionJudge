# 理论驱动的决策工作流实施计划

日期：2026-09-21。依据：用户确认按 `theoretical-foundations.md` 的顺序完善项目。

## 设计基线

沿用本地 React、TypeScript 与 IndexedDB 架构。先完善已有五步比较，再增加验证与投入、行动与复盘两个工作区。所有新增记录归属单项 Decision 聚合，继承自动保存、删除、备份与快照语义。没有账号、外部数据传输或自动代用户决策。

确定性加权比较仍是本轮的计算模型。未实现的情景、风险、因素和折现模块显示为规划内容，不再声称参与计算；新增理论提示注明来源和边界。完整高级数值模型及轻选择推荐器仍按产品路线后续交付。

## 阶段与验收

- [x] 比较基础：明确评分锚点、摆幅赋权引导、目标与方案提示；逐方案核实约束；评分依据与来源；修复零权重对齐与合法扰动；解释第一名相对替代方案的差异。未知底线允许条件比较，但不能确认选择。
- [x] 证据与投入：记录会改变决定的假设、验证渠道与结果；记录人民币和小时两类投入、可回收金额及承受边界；达到边界触发复评，不改变排名或自动退出。
- [x] 行动与复盘：如果—那么计划、障碍应对、复盘日期；事前登记可检验预期，封存原始预测后记录结果；复盘分别记录判断、执行、外部变化与下一步。
- [x] 集成与验证：旧记录无需破坏性迁移，新字段可选；导入验证与冲突重映射覆盖新增聚合和历史快照；自动保存与导航不丢最近输入；运行领域、应用和导入测试、构建及浏览器完整流程。

## 文件职责与数据契约

- `src/domain/evaluation.ts` / `types.ts`：加权比较、合法权重扰动、并列、条件可行性、差异解释。计算版本递增至 v2，旧快照封存结果不重算。
- `src/components/DecisionSteps.tsx`：五步比较和结果面板；通过 Decision 与 onUpdate 回调更新，不直接访问存储。
- `src/domain/workflow.ts`：DecisionWorkflow 类型、空状态、投入汇总、到期提醒和二元预测评分；函数不访问 DOM 或数据库。
- `src/components/DecisionWorkspace.tsx`：验证、账单、行动、预测和复盘；接收 `decision`、`section: "evidence" | "review"`、`onChange(workflow)`。
- `Decision.workflow?`：新工作流为可选内嵌对象。旧 Decision 缺失时按空工作流展示。Score 的来源、日期、依据类型和信心为可选字段。
- `src/application/decisionService.ts`：创建与快照；快照仅接受当前排名中的已核实可行方案，sourceRevision 与结果 evaluatedRevision 对齐。
- `src/application/backup.ts`：验证导入外形与引用，重映射冲突 Decision/Snapshot/Preset ID。历史快照原始 result 保留。
- `src/infrastructure/localRepository.ts`：事务保存，revision 检查和写入原子进行；不增加 object store。
- `src/App.tsx`：三个工作区导航、统一保存、错误展示、备份与快照集成。

DecisionWorkflow 中验证任务、投入、计划、预测、复盘均由所属决策拥有。删除决策时随聚合删除；快照深拷贝保留当时工作流。金额与时长分别汇总，绝不与主观评分直接相减；用户预设仅复制方案、维度、权重，不复制证据或执行历史。

## 验证案例

领域测试覆盖零权重位于数组中间、极端权重、双向扰动、并列、差异贡献求和、非有限输入、未知/不可行约束、未实现高级模块。工作流测试覆盖回收值不大于支出、金额与小时分离、零边界、日期到期、未决预测不评分、原始预测不被结果回填覆盖。

应用测试覆盖旧格式兼容、快照独立且版本一致、删除方案清理引用、备份回读与 ID 冲突、非法输入全量拒绝。浏览器检查覆盖创建→约束→赋权→证据→结果→验证与投入→行动→复盘→刷新与备份，并检查窄屏无横向溢出。

本轮验收证据（2026-09-24）：pnpm test 通过 7 个测试文件、112 项测试；pnpm build 通过；Microsoft Edge 隔离浏览器流程覆盖桌面与 390px 窄屏，并确认控制台无运行时错误。完整高级数值模型（情景、风险偏好、因素层次、折现）和推荐器仍未参与计算。
