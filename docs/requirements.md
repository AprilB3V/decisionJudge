# DecisionJudge 需求基线

> 状态：已确认  
> 版本：1.0  
> 日期：2026-08-23

## 1. 产品定位

DecisionJudge 是一款面向个人用户的 Web 决策辅助工具。它服务于容易陷入选择困难、并希望提高决策效益的用户，通过结构化比较和场景化解释，帮助用户：

- 明确决策目标、约束与备选方案。
- 比较各方案的预期收益、未来成本和不确定性。
- 识别机会成本、沉没成本等常见决策概念。
- 获得可解释的方案排名，而不是被动接受“正确答案”。
- 在完成实际决策的过程中学习经济学思维。

## 2. 范围与阶段

决策按频率和重要程度分为四类：

| | 低重要性 | 高重要性 |
| --- | --- | --- |
| 高频 | 快速选择 | 持续优化 |
| 低频 | 简化比较 | 深度决策 |

MVP 仅实现“低频、高重要性”的深度决策，但数据模型应允许未来扩展其他类型。

MVP 为公开仓库的本地单用户应用，采用 Mozilla Public License 2.0（MPL-2.0）。可为未来商业化保留扩展能力，但不为未确定的商业需求预先增加系统复杂度。

产品交付分为两个阶段：

1. **本地自用版（MVP）**：无账号、无密码、无云端依赖，数据默认保存在用户设备中。
2. **云端服务版（后续）**：可优先考虑微信小程序，届时再引入身份认证、云端存储和跨设备同步。

## 3. 用户与核心场景

### 3.1 用户

- 主要用户：需要处理个人重大选择的普通用户。
- 前置知识：不要求具备经济学、统计学或决策理论背景。
- 使用目标：降低结构化决策的心智负担，而不是增加一套专业工具的学习成本。

### 3.2 首批模板

1. 空白模板。
2. 换工作。
3. 选择城市。
4. 重大消费或购房。
5. 升学还是就业。

模板提供推荐维度、评分锚点和经济学提示；用户可增删维度、修改权重并补充自己的评分依据。

## 4. 产品原则

1. **可解释优先**：所有分数和排名都必须能追溯到用户输入、权重和明确规则。
2. **辅助而非代替**：系统给出排名、优势和稳定性，不宣称存在客观正确的选择。
3. **未来增量优先**：比较从现在开始各方案带来的新增收益和成本。
4. **教育融入流程**：概念解释出现在相关操作现场，不要求用户先学习一门课程。
5. **渐进式复杂度**：基础模式可独立完成决策；高级模式用于专业微调，不应成为必填流程。
6. **渐进式披露**：创建决策后按“明确问题、列出方案、设置权重、逐项评分、查看结果”分步呈现。每一步只显示当前认知任务，允许返回修改并持续自动保存，不要求用户一次面对完整表单。

## 5. 基础模式

基础模式必须保持简洁易懂，用户只需接触必要的决策概念。

### 5.1 输入

- 决策标题、目标和预计做出决定的日期。
- 至少两个备选方案，并提示用户加入“维持现状”。
- 不可妥协的硬约束，用于先排除不可行方案。
- 由模板提供的评价维度，以及用户调整后的权重。
- 各方案在每个维度上的 1–10 分评分，每个维度应有可理解的评分锚点。
- 薪资、学费、通勤时间等客观数值可作为评分依据记录，但基础模式下仍由用户给出 1–10 分，不制造虚假的计算精度。
- 与决策相关的已投入金钱、时间或精力，用于识别沉没成本。

### 5.2 计算与输出

- 权重总和为 100%。
- 基础效用分为各维度标准化评分的加权和。
- 给出可行方案的排名及综合分数。
- 展示每个方案的主要优势、主要劣势和影响结果最大的维度。
- 展示选择某方案所放弃的最佳可行方案，作为机会成本的解释。
- 展示最高分方案相对次优方案的净优势。
- 已发生且无法收回的沉没成本默认不进入方案得分，但应显示原因。
- 显示简单敏感性分析：权重小幅变化是否会改变第一名。

### 5.3 基础教育内容

- 稀缺性与约束。
- 机会成本。
- 沉没成本。
- 权衡取舍。
- 预期收益与未来成本。

## 6. 高级模式

高级模式通过明确的切换按钮开启。开启或关闭不得丢失用户数据；当高级参数会改变基础结果时，系统必须明示。

页面上的高级模式总开关只控制专业界面的展开与折叠，不撤销已配置的计算。每个高级模块拥有独立的启用开关；折叠后如仍有高级模块生效，基础页面和结果页必须显示“高级参数生效中”。

### 6.1 维度内因素

- 一个维度可拆分为多个因素。
- 例如“职业发展”可拆分为晋升空间、技能成长、行业前景和人脉积累。
- 因素可设置维度内权重，维度分数由因素加权汇总。
- 必须防止同一影响被多个高度重叠的因素重复计分。
- 客观数值可配置理想值、可接受底线和评分方向，由系统按可解释的规则换算为维度或因素评分。

### 6.2 可选专业参数

- 乐观、基准、悲观三种情景及其概率。
- 基于情景概率的预期效用。
- 用户的风险偏好，以及下行结果对推荐的影响。
- 跨期金钱流、时间范围与折现率。
- 相对“维持现状”的边际收益和边际成本。
- 更精细的权重敏感性分析和方案稳定区间。
- 高级经济学概念的场景化解释，包括时间价值、边际分析、风险偏好和边际效用递减。

## 7. 完整用户流程

1. 打开本地应用，无需注册或登录。
2. 创建决策并选择模板。
3. 在“明确问题”步骤设定目标、时间范围和硬约束。
4. 在“列出方案”步骤添加或删除方案，确认是否包含“维持现状”。
5. 在“设置权重”步骤确认模板维度和权重，可选开启高级模式微调。
6. 在“逐项评分”步骤按评价维度依次为各方案评分。
7. 在“查看结果”步骤查看方案排名、解释、机会成本和敏感性。
8. 确认最终选择并保存当时的不可变决策快照。

## 8. AI 扩展边界

AI 不属于 MVP 的必需能力，但系统设计应为后续扩展保留边界。

- 用户可在未来配置个人 API 密钥。
- AI 可辅助追问遗漏方案、维度和前提，识别可能的认知偏差，并解释计算结果。
- AI 不得直接替用户做决定，不得无说明地改变评分或权重。
- 若未来商业化，再评估由平台提供模型服务或自训练模型。

## 9. 本地数据与后续云端服务

- MVP 不包含账号、密码、身份认证或云端同步。
- 决策数据默认仅保存在用户设备中，不发送到第三方服务。
- 用户应能删除本地决策记录。
- MVP 应支持导出和导入可移植的决策数据，以便用户备份并为未来迁移到云端做准备。
- MVP 提供空白模板；用户可将当前方案、评价维度和权重保存为本地预设，之后重复使用或删除。
- MVP 不支持多人协作编辑或只读分享。
- 后续云端版可以微信小程序为主要入口，但账号映射、数据同步、隐私政策和运营合规属于届时的独立需求。

## 10. 非功能需求

- 响应式 Web，覆盖主流桌面端和手机屏幕。
- 决策编辑过程应在本地自动保存，避免意外丢失长时间填写的内容。
- 普通用户无需阅读经济学说明即可完成基础模式。
- 相同输入和计算版本必须产生相同结果。
- 结果页必须揭示计算方法、关键假设和数据不完整性。
- 决策内容和未来的个人 API 密钥必须按敏感数据处理。
- 首版界面使用简体中文，实现时应集中管理界面文案，为后续国际化保留结构。

## 11. MVP 范围外

- 团队决策和多人实时协作。
- 账号系统、云端存储、跨设备同步和微信小程序。
- 由平台提供的 AI 模型服务或自训练模型。
- 自动为用户做出最终选择。
- 专业投资、医疗、法律或企业风险决策建议。
- 高频或低重要性决策模式。
- 独立经济学课程或考试系统。

## 12. MVP 验收场景

1. 用户能选择“升学还是就业”模板，添加至少两个方案，完成评分并获得可解释的排名。
2. 当用户录入不可收回的已投入成本时，该成本不改变方案排名，系统说明这是为了避免沉没成本谬误。
3. 当用户查看任一方案时，系统能指出选择该方案所放弃的最佳可行方案。
4. 当小幅改变一个维度权重就会改变第一名时，结果页明确提示结论不稳定。
5. 用户能开启高级模式，将一个维度拆成多个因素并分配维度内权重，结果页能解释分数变化的原因。
6. 关闭高级模式后，高级输入仍被保留；如果它们仍参与计算，页面必须显示明确状态。
7. 关闭并重新打开本地应用后，用户能继续编辑已自动保存的决策。
8. 用户能确认最终选择，并保存不随后续编辑而变化的决策快照。
9. 用户能将本地决策导出为可移植数据，删除本地数据后再导入，关键决策内容和计算版本保持一致。
10. 用户创建决策后一次只看到一个步骤的输入内容；可以通过上一步、继续或步骤导航返回修改，切换步骤不会丢失已填写数据。
11. 用户能从空白模板自行添加方案和评价维度；保存预设后可在模板区创建一项新的空白评分决策，且预设不带入旧评分或结果。

## 13. 已确认的产品决策

1. 基础模式保留客观原始数值，但不自动把它们包装成精确效用；自动换算属于高级功能。
2. 高级界面折叠后，已启用的高级模块继续参与计算，并必须显示生效状态。
3. MVP 保存不可变的决策快照；实际结果记录和系统化复盘放入后续版本。
4. MVP 为无账号的本地自用版；云端服务优先考虑微信小程序。
5. 首版界面使用简体中文，项目采用 MPL-2.0。
6. 预设属于本地结构资产；导出备份可携带预设，导入时与现有 ID 冲突的预设会生成新 ID，不覆盖现有内容。
