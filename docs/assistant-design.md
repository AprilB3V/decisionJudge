# 简洁模式与问答设计助手

日期：2026-09-24。用户要求默认简化权重与评分，增加专业模式和兼容 OpenAI API 的问答助手。

## 交互与验收

- 默认普通模式：权重页仅保留维度名称、单个百分比输入、备注；评分页仅保留方案评分和备注。权重可一键按比例调整到 100%。专业模式复用已有锚点、摆幅、证据类型、信心、来源和日期，切换模式不改变数据或计算。
- 每个决策使用已有 `advancedUiExpanded` 保存模式，普通模式为新建默认值。验证与复盘入口保持可用；旧数据不删除。
- 比较页提供“问答梳理”入口，展开助手时隐藏手动比较表单，保存配置后收起设置。API 设置包含兼容接口地址、模型、仅内存密钥和可编辑预设系统提示词。提供通用、职业、消费三组预设；非密钥配置保存本机，不进入决策备份。
- 用户发送时，向配置的服务商发送当前问题、方案、维度、底线和本轮聊天；不自动请求，不发送其他决策、执行历史、评分证据或 API 密钥以外的凭据。界面提前说明传输范围与服务地址。
- 每轮只提一个主要问题，允许用户“不确定”，不编造偏好或数据。设计结果由用户预览后应用，不直接写入评分或确认选择。
- 应用草稿会替换目标、方案、维度和底线并清空评分。保留当前决策 ID、执行记录和历史快照；通过现有 session 校验与自动保存。若比较输入在问答过程中变化，则旧草稿不可应用，需重新整理。

## 模块与数据

- `domain/assistant.ts`：提示词预设、结构化建议 schema、上下文投影与草稿转换。建议 DTO 不含数据库 ID，Zod 检查有限权重、非空且不重复的方案/维度及数组规模；应用时生成 ID、归一化，硬约束状态均为未知，分数均为 null。
- `infrastructure/assistantClient.ts`：fetch Chat Completions，非流式文本/JSON响应；HTTPS 或本机 HTTP，禁止 URL 凭据、查询和片段；禁止重定向携带密钥；60 秒超时、取消、HTTP 状态与响应校验。失败信息不回显服务响应或密钥。
- `infrastructure/assistantSettings.ts`：localStorage 仅保存地址、模型、预设 ID 和自定义提示词。密钥只在模块内存，刷新清除；聊天仅在编辑器会话保留，离开或刷新清除。
- `components/DecisionAssistant.tsx`：连接设置、问答、取消、错误、预览/确认；在切换普通/专业、比较步骤时保留会话，关闭后取消在途请求。
- `components/Editor.tsx`：模式切换、助手挂载与应用新草稿后导航到权重；保存锁期间禁止应用。

## API 契约

`POST {baseUrl}/chat/completions`，也接受完整 endpoint；`Content-Type: application/json`，有密钥时 `Authorization: Bearer ...`。请求 `{model, messages:[{role,content}], stream:false}`。基础地址应包含服务要求的版本前缀，例如 `/v1`。不要求提供商支持 tools 或 response_format。

系统要求返回 `{"message":"本轮总结或问题","proposal":null}`；准备就绪时 proposal 为 `{title,objective,options:[{name,description,isStatusQuo}],criteria:[{name,description,weight,lowAnchor,highAnchor}],constraints:[{label,description}]}`。正常纯文本回复作为问题展示；出现无效结构化结果则报可重试错误，不应用部分内容。未知扩展字段不转写到 Decision。
