# DecisionJudge 0.3.0 上线评估与缺陷修复复验

评估日期：2026-09-24。目标：**少量用户试用，独立 HTTPS 静态网站，平台待定**。文档先记录初次评估结果；随后已修复 R1/R2 并完成复验。本轮仍未部署，提交与推送在复验完成后进行。

## 结论

**两个数据保护缺陷已修复并通过复验；项目可进入候选发布冻结，完成版本签出和正式 HTTPS 验收后再邀请少量用户试用。** 核心功能、构建和正常流程已达到候选版本水平，无需为首轮增加账号、服务器端数据库或云同步。

这不是对所有历史需求的完整交付证明：情景概率、折现、因素层次和风险偏好数值计算仍未实现。专业模式当前指更详细的编辑界面，发布介绍应与 README 的 0.3 范围一致。

## 已修复并复验

### R1 / P1：删除确认保护

- 修复：[App.tsx](../src/App.tsx:50) 在删除前读取记录和快照数量，并显示包含决策名称、快照数量和不可撤销提示的确认框；取消会保留全部内容。
- 复验：生产构建浏览器探针先取消、再确认删除，结果为取消后 `1 决策 / 1 快照` 保留，确认后为 `0 / 0`，共出现 2 次确认对话框。详见 [探针结果](./release-evidence/2026-09-24/browser-probes.json)。
- 回归保护：核心流程脚本覆盖确认后的删除结果；后续若改为自定义对话框，应继续保留取消路径测试。

### R2 / P1：跨日失败保存重放

- 修复：[workflow.ts](../src/domain/workflow.ts:244) 增加仅供仓储重放的受控选项，要求原始预测字段一致且下一状态通过完整封存/结算校验；[localRepository.ts](../src/infrastructure/localRepository.ts:65) 仅在持久化转换使用该选项。交互层仍拒绝从未封存直接结算。
- 复验：`localRepository.test.ts` 覆盖“封存写入失败→截止日后结算→恢复重试”，最终记录成功落盘；既有封存字段和复盘不可变保护测试仍通过，共 133 项测试通过。
- 文档差异：`docs/api.md` 关于持久化重放的说明现与实现一致。

### R3 / 发布门槛：形成可追溯、可回滚的候选包

修复前评估时工作区包含大量未提交/未跟踪实现；本轮会在推送前形成可追溯候选提交。仓库仍未提供部署流水线、Node/pnpm 版本约束或主机响应头配置。已有锁文件可固定依赖，`latest` 本身不意味着冻结安装一定漂移，但重新解析依赖会变动。

## 静态网站上线方案

1. **固定 HTTPS origin**：选择稳定域名后再邀请用户。IndexedDB 按协议、主机和端口隔离，`localhost:5173`、预览域名和正式域名不会自动共享数据。切域名前从旧地址导出、在新地址导入，不能宣称原记录丢失或自动迁移。
2. **构建根目录**：以包含 `package.json` 的目录为准，当前 Git 根目录即项目目录；若上传的是外层工作区，则需进入其中的 `decisionJudge/`。安装全部构建依赖，运行测试、构建，发布 `dist/`。当前资源绝对路径以 `/assets/` 开头，子路径托管需配置 Vite `base` 后另验收。
3. **缓存与回滚**：HTML 要求重新验证，带 hash 的静态资源可长期 immutable 缓存。避免回滚时删除旧资源导致已打开页面失效；保持域名和 IndexedDB schema，不通过清库回滚。
4. **响应头**：在所选主机上配置并实际验证 `X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、禁止第三方 frame 嵌入。CSP 应结合用户可配置的 HTTPS API：`connect-src 'self' https:` 可支持兼容服务，但不是域名白名单隔离；样式有内联 style，严格 CSP 需先报告模式测试。不要为了助手配置开放 CORS 代理。
5. **用户数据说明**：产品内补充可直接找到的备份/恢复、浏览器数据清理影响、换设备/域名不自动同步说明。API 请求内容由所配置服务处理，站点自身日志不应收集决策文本或密钥。静态主机是否记录访问日志以平台实际设置为准。
6. **试用支持**：提供一个明确的问题反馈入口及版本号。故障报告收集浏览器、操作步骤、错误类别，默认不索取完整决策或密钥。无需先引入复杂遥测平台。

未确定平台，因此生产证书、安全头、CDN 缓存、地域可访问性和回滚按钮仍是待验收项；本地 preview 的结果不能替代这些检查。没有 service worker，不应对外承诺离线刷新也能打开网站。

## 建议的首轮试用

- 范围：先邀请 5–10 人、约一周；这只是建议，尚未邀请或发送消息。
- 主任务：从模板或问答创建一项决策，完成两方案/三维度比较，解释最大取舍，保存、刷新并导出/导入一次。
- 建议放行观察指标：至少 4/5 用户无需讲解完成普通流程；零不可恢复数据丢失；无导致无法继续的保存错误；用户能说清权重与分数的区别。助手单独记录连通成功、有效草稿和明显不合理提问，不与本地流程混为一项成功率。
- 用户已指出认知负担较高，不能以“字段少了”代替真实用户验证。优先观察用户是否仍卡在权重与评分、是否会误把建议权重当成客观事实。
